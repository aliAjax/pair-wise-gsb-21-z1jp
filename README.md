# hxwl-07 发动机孔探复核台

在原航空维修检查清单上扩展的孔探复核工作台：按发动机与孔探站位登记叶片编号、缺陷长度/深度、
参照尺寸、检查人与仪器校准期，并对放行流程做强制管控。

## 技术栈

React + Vite + TypeScript + CSS，数据本机保存在浏览器 IndexedDB（无后端、无第三方运行时依赖）。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：5107

## 业务规则（判定层 `src/rules/`）

- 登记的每条孔探记录统一进入 **待评估**，不存在“登记即放行”。
- 出现以下任一情况时记录停在待评估，并在放行签署区逐条列出：
  - 缺陷长度较上次（同一发动机 / 站位 / 叶片编号的最近一次**已放行**读数）增长 **超过 1mm**；
  - 所选孔探仪校准有效期已过；
  - 检查人无检查授权或资质已失效。
- 放行必须满足：
  - 由**另一名**放行人员（不是检查人本人，且资质有效、具有放行授权）签署；
  - 填写工程依据（限长数据 / AMM 或 CMM 条款 / 工程偏离批准编号）；存在阻断项时，
    工程依据须覆盖该阻断（如换叶批准、偏离编号）。
- 放行后读数锁定，不可直接覆盖。
- 已放行记录如需更正：由放行人员填写更正原因，旧读数、旧检查人、旧仪器、旧检查日期
  **另存为版本并永久保留**，记录回到待评估并清空原签署，需重新放行。
- 重开页面可按发动机查看：待办列表、各站位叶片本次与上次读数对比（超 1mm 红色标出）、
  版本号与更正次数。

## 分层结构（四层分开维护）

| 层 | 目录 | 职责 |
| --- | --- | --- |
| 资料 | `src/data/` | 领域类型 `types.ts`、种子资料 `seed.ts` |
| 判定 | `src/rules/` | 阻断判定 `evaluation.ts`、状态流转 `actions.ts`（纯函数，不碰 DOM 与存储） |
| 本机保存 | `src/storage/` | IndexedDB 封装 `db.ts`、仓库 `repository.ts`、React 数据钩子 `useDatabase.ts` |
| 页面 | `src/pages/`、`src/components/` | 按发动机复核、孔探登记、资料维护三个页面及登记表单、记录详情抽屉 |

首次打开时种子资料写入本机库，之后全部读写本机库；清空站点数据可恢复示例。
